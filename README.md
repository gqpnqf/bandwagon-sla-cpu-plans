## SLA 具体保障什么？

官方 SLA 约定的目标是：符合条件的 VPS 在每个自然月达到至少 99.99% 月度在线率。计算时以服务商监测记录为主要依据；若用户认为当月未达标，需要提交明确的 SLA Service Credit 申请，并在停机月份结束后的 90 天内提出。符合条款时，补偿以增加 VPS 预付服务时间的形式提供，不是现金。

限制也要看清楚。计划维护、用户自己的软件或配置问题、按套餐规则施加的资源限制、DDoS 等安全事件，以及服务商无法控制的第三方网络问题，都可能被排除在 SLA 计算之外。SLA 是针对符合定义的网络或物理主机可达性问题，不是对应用程序、数据库或所有网络路径的全面担保。

购买前可以核对三件事：订单是否明确标为 SLA Plan；你关心的故障类型是否落在 SLA 定义内；若发生中断，申请服务补偿的时限和材料要求是什么。只看到“99.99%”几个数字就下单，信息还不够。

## 怎么选合适的独享 CPU 档位？

先从工作负载出发，而不是从最高配置往下挑。

- **小型服务或轻量网站**：如果 CPU 使用率大部分时间很低，先比较 1 GB 或 2 GB 内存档是否满足应用需求。内存不足时，加 CPU 核心并不能解决交换分区频繁的问题。
- **持续跑后台任务**：重点看任务的并行能力、峰值内存占用和任务持续时间。单线程程序未必能充分利用更多核心。
- **多服务部署或数据库负载**：优先核算内存和存储空间，再看 CPU。数据库缓存、日志和备份都要占资源。
- **流量较大的应用**：对照月流量和端口速度，不要把高带宽等同于无限流量。套餐表里的流量额度仍然是一个明确限制。
- **需要可用性条款的业务**：认真读 SLA 排除项和申诉流程。99.99% 是月度目标，且有适用条件，并不意味着业务无需自行做好备份、监控和故障恢复。

如果尚不确定瓶颈在哪里，可以先记录一段时间的 CPU、内存、磁盘 I/O 和网络使用情况。观察到 CPU 长时间接近满载，再考虑独享 CPU；如果主要是磁盘等待或内存耗尽，应针对对应资源做调整。

## 搬瓦工独享 CPU 常见问题

### 独享 CPU 是否意味着物理服务器只有我一个用户？

“AMD dedicated CPU”是套餐对 CPU 资源的描述，不能据此推断整台物理服务器、磁盘和网络接口都由单一客户独占。下单前应以产品条款对资源分配的具体定义为准。

### 买更多核心，网站一定更快吗？

不一定。多核对能够并行处理任务的程序更有帮助；单线程任务、数据库等待或网络延迟，未必会因为核心数增加而明显改善。先定位瓶颈，通常比直接升级到大档位更有效。

### 99.99% SLA 是否代表全年最多停机约 52 分钟？

99.99% 是按月计算的在线率承诺，且排除项和申请条件会影响结果。把它简单换算成全年固定停机额度，不能代替官方条款的月度计算方式。补偿也需要按规则申请，形式为额外预付服务时间。

### 搬瓦工独享 CPU 有优惠码吗？
